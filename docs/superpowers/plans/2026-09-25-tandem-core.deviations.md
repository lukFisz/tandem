# Tandem core — deviations from the plan

Deviations from `2026-09-25-tandem-core.md` (and from the spec where the plan already differed), recorded during implementation.

## Decided before implementation

- **Oversized files (Task 13).** Any file over 1 MiB is rejected, even with `--lines`. The `file_too_large` hint no longer suggests `--lines`; it suggests pasting the relevant part as a block via stdin.
- **File error hints (Task 13).** `file_not_found` and the binary-file error now carry specific hints, and the tests assert them.
- **`wait` delivery (Task 10).** The handler writes and flushes the response before marking events delivered, and marks them only if the write succeeded (at-least-once). A handler-level test with pending events and a cancelled request context pins this.
- **File modes (Tasks 14, 15).** The `0600`/`0700` rule covers Tandem's own state under `TANDEM_HOME`. `tdm export --out` and `tdm skill install` write user-facing files with `0644`/`0755`.
- **HTTP routes (Task 9, vs spec §7).** The plan's routes are kept: `POST /api/sessions` (project in the body) and `GET /api/sessions/{sid}/blobs/{sha}` (blobs are stored per session), plus the plan's extra routes.
- **Upcasting (vs spec §8, §13.2).** Not implemented: every event type is at `v: 1`.
- **Chat (vs spec §6).** There is no `chat.message` event; a chat message is a `review.submitted` with a `message`.
- **Awaiting AI (vs spec §3).** A thread awaits the AI when it has user events after the AI's last action, whether or not they were delivered yet.
- **Tests (vs spec §13).** Render tests use inline expected strings instead of golden files. The e2e test adds a daemon restart-and-resume scenario. `schema/` is left to plan 2.

## During implementation

- Task 2: the plan's `events.go` and `state.go` both declare an identifier `SessionClosed` (an event payload struct vs. a `SessionStatus` constant) and both declare `StageSummaryProposed` (an event payload struct vs. a `StageStatus` constant) — an illegal redeclaration in Go's single package namespace. Per a controller ruling, the status constants `SessionClosed` and `StageSummaryProposed` are kept exactly as in the Interfaces block; the two event-payload structs are renamed to `SessionClosedPayload` and `StageSummaryProposedPayload` (same fields and JSON tags). Later tasks (at least Task 3 and Task 9) must construct/decode `EvSessionClosed` and `EvStageSummaryProposed` payloads using these new struct names, not the plan's original text.
- Task 4: `decide.go` constructs `SessionClosedPayload{}` and `StageSummaryProposedPayload{...}` (per the Task 2 ruling above) instead of the plan's `SessionClosed{}`/`StageSummaryProposed{...}`. `TestThreadsUnresolvedHintListsThreads` in `decide_test.go` guards the failure path with a `t.Fatalf` when `errors.As` fails or returns a nil `*Error`, instead of dereferencing `de.Hint` directly (preflight nit).
- Task 6: `Manager.Sessions` iterates a sorted (by session id) slice instead of the plan's unordered map range, so its result order is deterministic (preflight nit). The `session_not_found` `*domain.Error` (with its hint) is built once by a `sessionNotFound(sid)` helper and reused by `Manager.getLocked` and `Manager.SetActive`, instead of each constructing its own literal (Ruling D4).
- Task 6: `store.Log.f` changed from `*os.File` to an unexported `logFile` interface (same method set `*os.File` already has), and `Log.Append` now records the file offset before writing and, on any write or sync error, truncates back to that offset and reseeks to the end before returning the error. This closes a gap where a short write left a torn line the log could never reload past, or a write-succeeds/sync-fails split left bytes on disk that `s.events` did not know about, so the next append would reuse the same seq. `Log`'s exported signature is unchanged. Covered by `internal/store/log_fault_test.go` (`TestAppendRecoversFromWriteFailure`, `TestAppendRecoversFromSyncFailure`), which inject a one-shot write/sync failure via a fake wrapping the real file and then assert the log reloads cleanly with strictly increasing seqs.
- Task 6: `Session.MarkDelivered(upTo)` now clamps `upTo` to `state.LastSeq` before comparing it to `state.Delivered`, so a caller can never mark an event that has not been written yet as delivered (Review Focus 5). Covered by `TestMarkDeliveredClampsToLastSeq`.
- Task 8: the brief's Interfaces block lists `human` as a helper already produced by Task 7, but no such identifier exists anywhere in the repo (Task 7's `wait.go`/`md.go` do not define it). Added a small unexported generic helper `human[T ~string](status T) string` in `internal/render/views.go` (replaces `_` with a space in a status constant) and used it for stage/thread status text in `Show` and `Summarize`. No exported API changed.
- Task 10, corrected in fix round 1 (the original bullet here was inaccurate): `TestWaitSuperseded`'s two goroutines and `TestWaitWakesOnNewEventAndJSONFormat`'s goroutine called `e.do`/`e.userMessage`, which call `e.t.Fatal`/`e.t.Fatalf` on failure — not allowed off the test goroutine by `testing` (preflight nit). Calling `e.do` from a goroutine is itself the bug, regardless of whether the transport-error path is likely to trigger; round 1 fixes it for real. Added `testEnv.tryDo` (server_test.go) and `testEnv.tryUserMessage` (wait_test.go), non-fatal counterparts of `do`/`userMessage` that return `(int, string, error)`/`error` instead of calling `t.Fatal`. `TestWaitSuperseded` and `TestWaitWakesOnNewEventAndJSONFormat` now call these from their goroutines and send the result over a channel; only the test goroutine calls `t.Fatal`.
- Task 10: Step 2 (verify RED) actually failed at compile time (`e.srv.wait undefined`, `undefined: Run`) rather than the brief's described runtime "placeholder page" failure for the wait tests — as the brief's own Step 2 note anticipated, since none of `wait.go`/`stream.go`/`run.go` existed yet.
- Task 10 (Ruling R3 / Review Focus 5): added `TestWaitHandlerDoesNotDeliverOnAlreadyCancelledContext`, a deterministic handler-level test (pending user events + an already-cancelled request context passed straight to `(*Server).wait` via `httptest`) — the plan's `TestWaitDisconnectDoesNotDeliver` never has pending events during the disconnected wait, so alone it does not exercise the `ctx.Err()` guard. The `wait` handler itself follows R3's order (write the body and flush, then mark delivered only if the write succeeded; a `MarkDelivered` failure after a successful write is logged, not turned into an HTTP error, since the response is already committed at that point) rather than the brief's literal code, which marks delivered before writing.
- Task 10, fix round 1 (review findings 1–2): the `ctx.Err() != nil` branch in `wait()` no longer just `return`s (which sent an empty 200 for a still-live-but-cancelled client, breaking the spec §6 "previous waiter gets `wait_superseded`" contract when ctx was cancelled by a *superseding* wait or daemon shutdown rather than a real disconnect) — it now calls a new `respondCause(w, ctx)` helper (also used by the pre-existing `ctx.Done()` branch) that answers 409 `wait_superseded` or 503 `daemon_stopping` per `context.Cause(ctx)`, still without marking anything delivered. Also, `http.Flusher.Flush()` (used after a successful `w.Write`) silently discards errors, so a buffered small body could report a successful write/flush even though the connection was already dead, defeating the "mark only if the write succeeded" guard; switched to `http.NewResponseController(w).Flush()`, whose error is checked before `MarkDelivered` (works with `httptest.ResponseRecorder`, which falls back to the plain `Flush()` method). Covered by `TestWaitHandlerDoesNotDeliverOnAlreadyCancelledContext` (now also asserting `rec.Code == 503`) and the new `TestWaitHandlerRespondsSupersededWithPendingEvents`.
- Task 10, fix round 1 (review finding 4): the open-redirect fix from round 0 (`Task 10: carried Task 9 review minors ...`, item a) trimmed only `/` from the redirect path, which a backslash variant (`GET /%5Cevil.example/x?token=<valid>` → `Location: /\evil.example/x`, which browsers normalise to `//`) still slipped through. `strings.TrimLeft(r.URL.Path, "/")` is now `strings.TrimLeft(r.URL.Path, "/\\")`. Covered by a second case added to `TestTokenQueryRedirectRejectsProtocolRelativePath`.
- Task 10: carried Task 9 review minors #1, #2, #4, #5 into this task (same package): (a) the token-exchange redirect in `server.go`'s `guard` now builds its target as `"/" + strings.TrimLeft(r.URL.Path, "/")` plus the remaining query instead of reusing `r.URL.RequestURI()`, closing an open redirect for protocol-relative paths (`GET //evil.example/x?token=<valid>`); covered by `TestTokenQueryRedirectRejectsProtocolRelativePath`. (b) `s.activity.Touch()` now runs only after the Host/Origin/token checks succeed (and not for `/health`), so unauthenticated or bad-host/origin requests no longer keep the daemon alive. (c) `api.go`'s `events` handler now copies the matching events into a slice inside `sess.Read` and encodes them to the response after releasing the session lock, instead of writing to the network while holding it (matching `state`/`render`). (d) unknown `/api/...` paths now get a JSON 404 (`mux.HandleFunc("GET /api/", apiNotFound)` / `"POST /api/"`) instead of falling through to the `GET /` placeholder page; covered by `TestUnknownAPIPathReturnsJSON404`.
- Task 11: per preflight nit, `startDaemonProcess`'s `cmd.SysProcAttr = &syscall.SysProcAttr{Setsid: true}` (which makes `internal/client` unix-only) was split out of `connect.go` into `internal/client/start_unix.go` (build tag `unix`, exports `sysProcAttr() *syscall.SysProcAttr`) and `internal/client/start.go` (the OS-independent parts of `startDaemonProcess`, calling `sysProcAttr()`), instead of one file mixing both. No exported API changed. `TestConnectReplacesOtherVersion` uses Ruling D6's `select` with a timeout instead of a non-blocking `select … default: t.Fatal`.
- Task 11, fix round 1 (controller review — spec §7 "one daemon per machine, single writer"): (a) `internal/daemon/run.go` `Run` now acquires a non-blocking exclusive `flock` on `Home/daemon.lock` (new unix-only `internal/daemon/lock_unix.go`, `acquireLock`/`releaseLock`) before creating its `Manager`, held for the daemon's whole lifetime, and fails with `"another daemon is running"` if another process already holds it — closing a race where two auto-starting CLI invocations (or a slow `/health`) could each start a daemon that appends to the same `events.jsonl`. Covered by `internal/daemon/run_test.go`'s `TestRunFailsWhenAlreadyRunning`. (b) `internal/client/connect.go` `Connect` now takes an exclusive, ctx-bounded, polling `flock` on `Home/start.lock` (new unix-only `internal/client/lock_unix.go`, `lockExclusive`/`unlockFile`) around the remove→start→poll sequence, re-checking `Existing` once it holds the lock so only the first of several concurrent callers actually calls `StartDaemon`; covered by `TestConnectStartsDaemonOnceUnderConcurrency` (4 concurrent `Connect` calls, `StartDaemon` invoked exactly once, all clients get the same `BaseURL`). (c) if the previous daemon is still answering `/health` after `waitGone`'s `shutdownTimeout` (new test var, was a bare 3s), `Connect` now gives up with `daemon_unavailable` and hint `` "run `tdm daemon stop` and try again" `` instead of starting a second daemon alongside a live one; covered by `TestConnectGivesUpWhenOldDaemonWontShutDown`. (d) the startup poll loop now `select`s on `ctx.Done()` instead of an unconditional `time.Sleep`, returning `ctx.Err()` promptly on cancellation instead of spinning until `startTimeout`; covered by `TestConnectHonoursContextCancellation`. No exported signatures changed (`Run`, `Connect`, `Existing`, `StartDaemon`, `startTimeout` are unchanged; the new `shutdownTimeout`, `lockExclusive`, `unlockFile`, `acquireLock`, `releaseLock` are all unexported).
- Task 11, fix round 2 (controller review of round 1 — a slow-but-alive daemon must not be mistaken for a dead one): (a) `internal/client/lock_unix.go` gained `lockHeld(path) (bool, error)`, a non-blocking probe (`LOCK_EX|LOCK_NB` then immediately release, per the ruling's suggested approach) that tells whether some other process holds a lock file. `Connect`, once it holds `start.lock`, now probes `Home/daemon.lock` with it before touching `daemon.json`: if held, a live daemon is just slow to answer `/health`, so `Connect` never calls `RemoveDaemonInfo`/`StartDaemon` and instead only polls `Existing` (bounded by `startTimeout`, ctx-aware) for it to answer, giving up with `daemon_unavailable`/`"try again or run \`tdm daemon stop\`"` rather than clobbering a live daemon's info; covered by `TestConnectDoesNotClobberLiveDaemonWithSlowHealth`. (b) `waitGone` now also waits (bounded by the same `shutdownTimeout`, ctx-aware) for `daemon.lock` to become free before declaring the old daemon gone, since the old process keeps holding it until its own `Shutdown`/`mgr.Close`/`releaseLock` finish (up to ~5s) even after `/health` starts failing; its signature changed from `waitGone(ctx, c) bool` to `waitGone(ctx, c, home) (bool, error)`. (c) a ctx cancellation during `waitGone` is now returned as `ctx.Err()` instead of being folded into a `daemon_unavailable` "did not shut down" error. (d) `internal/daemon/lock_unix.go`'s `acquireLock` now reports `"another daemon is running"` only for `syscall.EWOULDBLOCK`; any other `Flock` error is returned as-is instead of being mislabeled. (e) a missing `store.WriteDaemonInfo` error check in `TestConnectGivesUpWhenOldDaemonWontShutDown` is now checked. `waitGone` and `Connect` (both unexported call sites aside) keep their public shape — `Connect`'s and `Existing`'s exported signatures are unchanged.
- Task 12 (Ruling D1): factored the connect → session id → `Raw` GET → `status>=400` → `client.DecodeError` sequence, which the brief's literal code repeated in both `session show --json` and `view`, into one small unexported helper `(*app).rawGet(ctx, path) ([]byte, error)` in `internal/cli/app.go`; `view` and `session show --json` (`internal/cli/session.go`) both call it. No exported name or signature changed; this is the seam Task 14 (`wait`/`log`) is meant to reuse per the ruling. `go get github.com/spf13/cobra@latest` resolved to `v1.10.2` (with indirect `github.com/spf13/pflag v1.0.9` and `github.com/inconshreveable/mousetrap v1.1.0`).
- Task 13: the plan's shared `threadTextCmd(use, short, typ)` helper sends `map[string]string{"threadId": thread, "text": text}` as command data, but `internal/domain/commands.go` (Task 2) declares `Say` and `Conclude` as typed structs (`ThreadID`, `Text` with `json:"threadId,omitempty"`/`json:"text"`), not an untyped map — using a map would still encode correctly over JSON but silently loses the compile-time link to the actual command shape. Replaced the single generic helper with two small dedicated constructors, `(*app).sayCmd()` and `(*app).concludeCmd()`, each building its own `domain.Say{ThreadID, Text}` / `domain.Conclude{ThreadID, Text}` and calling `a.call(ctx, "say"/"conclude", ...)`; `internal/cli/app.go`'s `commands()` calls `a.sayCmd()`/`a.concludeCmd()` instead of the plan's `a.threadTextCmd("say", ..., "say")`/`a.threadTextCmd("conclude", ..., "conclude")`. - Task 13 (preflight nits): `content_test.go`'s `TestContentCommands` checks the `json.Unmarshal` error from `--json session show` (`t.Fatalf` on failure) instead of ignoring it. `code`/`file`/`variants` subcommands call `MarkFlagRequired` without checking its return value, as in the brief (it can only fail here for a programmer error — an unknown flag name — which would be caught immediately by any test exercising `--help` or the flag).
- Task 14 (Ruling D1): `wait` needs the raw HTTP status (204 means timeout, not an error) that `rawGet` (Task 12) deliberately hides behind its blanket `status>=400` check, so `rawGet` was split into a new unexported `(*app).rawGetStatus(ctx, path) (int, []byte, error)` — the same connect → session id → `Raw` GET sequence, status returned as-is — with `rawGet` now just `rawGetStatus` plus the `status>=400`/`DecodeError` check. `wait` calls `rawGetStatus` directly; `log` and `export`/`view` keep calling `rawGet` unchanged. Also: the brief's `wait` writes the daemon's raw JSON body to stdout unchanged, which has no trailing newline (`json.Marshal`, not an `Encoder`) on a successful (200) `--json` response; per the preflight nit ("`tdm wait --json` should end with a trailing newline"), `waitCmd` now appends `\n` after writing the body when `a.jsonOut` and the body doesn't already end in one (the 204-timeout path already gets its newline from `a.emit`'s `json.Encoder`).
- Task 13: `readStdin` (`internal/cli/app.go`, Task 12) is unchanged. It can still block forever if stdin is a non-TTY pipe that is never closed and no `--text`/argument is given (e.g. an agent invoking `tdm say` with no text and a pipe held open by another still-running process). This is Go's normal blocking-read behavior for a pipe with no EOF, not a bug specific to `tdm`; a robust fix would need a goroutine + `select` with a timeout or a way to detect "pipe with a still-live writer but no data yet" some other way, which was ruled out as a hack. ## Final review fixes

- Finding 1 (security §7 — cookie auth on non-/wait GETs, wait state change on a mere GET): `internal/daemon/server.go`'s `guard` now requires the literal "Bearer " prefix before treating an `Authorization` header as a bearer token (`strings.CutPrefix`, folded together with finding 9 below); `/api/sessions/{sid}/wait` now accepts only a valid Bearer token (cookie-only → 401 `unauthorized`), since it changes state as a side effect of a GET; and any other route accepted via the cookie alone (no valid Bearer) is now rejected with 403 `forbidden` when `Sec-Fetch-Site` is `same-site` or `cross-site` (absent, `same-origin` or `none` still pass). Covered by `TestBearerRequiresPrefix`, `TestCookieAuthRejectsSameSiteAndCrossSite` (`internal/daemon/server_test.go`) and `TestWaitRejectsCookieOnlyAuth` (`internal/daemon/wait_test.go`).
- Finding 2 (stale "dev" version never triggers a daemon restart): added `internal/cli/version.go` with `ResolveVersion(version string) string` — when `version == "dev"` it hashes the running executable (`os.Executable` + sha256) and returns `"dev-" + first 12 hex chars`, otherwise it passes `version` through unchanged. `cmd/tdm/main.go` now calls `cli.Execute(cli.ResolveVersion(version), ...)`, so both the CLI's own version comparisons in `client.Connect` and the daemon it starts (`daemon run` uses `a.version`) see the resolved value. Covered by `TestResolveVersionPassesThroughNonDev`, `TestVersionFromFileDiffersForDifferentContent`, `TestVersionFromFileSameContentSameVersion` (`internal/cli/version_test.go`).
- Finding 3 (guide/skill silent on the wait-timeout-vs-shell-tool-cap mismatch): added one line each to `internal/guide/guide.md` (step 3 of "The loop") and `internal/guide/skill.md` telling the agent to run `tdm wait` with its shell tool's timeout at its maximum (600000 ms in Claude Code) or pass a shorter `--timeout`. Covered by `TestGuideAndSkillMentionWaitTimeoutCap` (`internal/guide/guide_test.go`, new file); `TestGuideCoversEveryCommand` still passes unchanged.
- Finding 4 (Connect gives up instead of falling through when a mid-exit daemon's lock frees; `tdm daemon stop` returns before the process actually exits): `internal/client/connect.go`'s "lock held" branch now calls a new `waitForLockRelease` (polls for a healthy same-version daemon, but returns as soon as the lock frees instead of only timing out) and, when the lock frees before a healthy daemon appears, falls through to the normal remove→start path instead of returning `daemon_unavailable`. Separately, `waitGone` was exported as `client.WaitGone` and is now also called by `tdm daemon stop` (`internal/cli/loop.go`) after `/api/shutdown` returns, since that handler answers 200 and stops the server asynchronously (`internal/daemon/api.go`'s `go s.stop()`) — without waiting, the command could return before the process released `daemon.lock`. Covered by `TestConnectFallsThroughWhenLockFreesWhileHeld` (`internal/client/client_test.go`) and `TestDaemonStopWaitsForProcessExit` (`internal/cli/loop_test.go`).
- Finding 5 (`tdm wait` on a closed session times out and loops forever per the guide's "exit 3 → wait again"): added `domain.SessionClosedError(sessionID string) *Error` (used by both `Decide` and the new check) and the daemon's `wait` handler now checks the session's status before entering the poll loop, answering the domain `session_closed` error (400, with its hint) immediately instead of waiting for the timeout. The CLI's existing `status>=400 → client.DecodeError` path in `waitCmd` already turns that into exit 1 with `error: session_closed: ...`, so no CLI change was needed. Covered by `TestWaitOnClosedSessionReturnsSessionClosedImmediately` (`internal/daemon/wait_test.go`); `e2e/e2e_test.go`'s `TestFullLoop` pin updated from "wait on a closed session times out, exit 3" to "exits 1 with `error: session_closed:`".
- Finding 6 (`render.Quote` splits only on "\n", so "\r\n"/"\r" don't behave as line breaks): `Quote` (`internal/render/md.go`) now normalizes `"\r\n"` and lone `"\r"` to `"\n"` before splitting. Covered by `TestQuoteNormalizesCRLF` (`internal/render/md_test.go`, new file).
- Finding 7 (`conclusion.accepted` in `tdm wait` output omits the accepted text, contradicting guide.md's "Use the final text you are given"): the `EvConclusionAccepted` case in `internal/render/wait.go` now appends `render.Quote(p.Text)` under the "Accepted as proposed." line. Covered by `TestWaitConclusionAcceptedQuotesText` (`internal/render/wait_test.go`).
- Finding 8 (go.mod marks cobra `// indirect` though it's a direct import): ran `go mod tidy`; `go.mod` now lists `github.com/spf13/cobra v1.10.2` as a direct `require` with `mousetrap`/`pflag` still `// indirect`. No dependency added or removed.
- Finding 9 (bare token in `Authorization` accepted without the "Bearer " prefix): folded into finding 1's `server.go` change above (`strings.CutPrefix(r.Header.Get("Authorization"), "Bearer ")`, used only when the prefix was actually present). Covered by `TestBearerRequiresPrefix` (`internal/daemon/server_test.go`).
